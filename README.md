# Stream Fleet Autoscaler (Go)

实时流媒体实例的**动态扩缩容**与**多区域/多规格容量再平衡**控制器。以单线程
reconcile loop 的方式，把"实际容量"持续收敛到"期望容量"，并能在**进程重启、
节点失联、部分创建失败、排空失败**后继续收敛而不丢会话、不重复占用实例。

实例生命周期与负载指标由内置的**确定性模拟器**（`internal/provider`）与
**回环脚本输入**（`internal/loopback`）驱动：相同的脚本与配置必然产生相同的
决策序列，便于复现与测试。

## 目录结构

| 包 | 职责 |
|----|------|
| `internal/fleet` | 领域模型：实例 / 会话 / 操作记录 / 审计事件 |
| `internal/config` | 弹性上下限、指标窗口、冷却、并发度、区域/规格配置 |
| `internal/metrics` | 有界滑动窗口与连续越限计数（迟滞判定） |
| `internal/provider` | 基础设施后端接口 + 确定性模拟器（延迟/失败/失联脚本） |
| `internal/store` | 期望容量、操作日志、事件日志的持久化（内存 / 原子 JSON 文件） |
| `internal/scheduler` | 均匀分布的会话放置（最少负载优先，ID 平局） |
| `internal/placement` | 扩容放置：按区域权重均匀分配，计入在途容量、受上限约束 |
| `internal/scaler` | 纯函数迟滞扩缩容策略（同输入同输出，可复现） |
| `internal/drain` | 安全缩容：空闲优先、优雅排空、超时后原子迁移 |
| `internal/rebalance` | 加权份额再平衡：独立区域冷却、稳定阈值、不掏空区域 |
| `internal/reconcile` | 重启/失联恢复：采纳在途创建、孤儿会话再调度、超时补偿 |
| `internal/controller` | 每个 tick 的确定性收敛循环（把上述组件串起来） |
| `internal/loopback` | 脚本化时序输入（负载/失联/重启/粘性会话）回放 |
| `cmd/autoscaler` | 负载突增→回落的端到端演示 |

## 每个 tick 的收敛顺序

控制器是**单线程**的，每个 tick 严格按以下顺序执行，保证状态一致、可追溯：

1. **推进并观测**：推进模拟后端，读取权威的实例/会话视图。
2. **恢复**：
   - `AdoptCreates`：把仍处于 `Pending` 的创建操作与后端实际状态对账——
     已 `Running` 即采纳成功，已 `Failed/Lost` 即记失败，仍 `Pending` 则继续
     等待，**绝不重复下发**已完成或在途的创建。
   - `RecoverLost`：识别失联节点；其会话在后端被摘除（`InstanceID==""`），
     由 `RescheduleOrphans` **恰好一次**地重新放置到同区域健康实例。
   - `TimeoutOps`：超时操作记终态；对创建类操作做补偿（释放已确认但不可用
     的容量），**绝不**强杀仍承载会话的排空实例。
3. **指标 + 策略**：逐区域计算 `报价负载 / 在跑容量`（利用率不封顶，使过载
   在容量饱和后仍然可见），跨区域取平均写入窗口；纯函数策略输出扩/缩/保持。
4. **收敛 actual → desired**：在并发度与上下限内，下发最少的创建/排空。
5. **推进排空**：只终止真正空闲的节点；有在途会话时优雅等待，超过
   `drainTimeoutTicks` 才**原子迁移**，无目的容量则继续等待，绝不丢会话。
6. **再平衡**：仅在稳定状态且偏离超阈值时，每 tick 至多做一次区域间迁移，
   先建后 drain，容量不出现凹陷。
7. **持久化**：追加审计事件并保存期望容量与操作日志（文件存储为
   临时文件 + rename 原子写）。

## 关键收敛语义（对应需求）

- **迟滞防抖与可复现**：需要连续 `scaleUpAfter`/`scaleDownAfter` 个窗口越限，
  且满足上/下冷却时间才动作；上下阈值之间为死区。策略是纯函数，输入序列
  相同时输出完全一致（见 `TestReproducibleDecisions`）。
- **容量放置与预留**：按区域权重均匀分配；`Pending`/`Draining` 容量计入，
  避免重复分配；任何时候非终态容量都被钳制在 `[minReplicas, maxReplicas]`。
- **安全缩容**：先回收**确证空闲（0 在途会话）**的节点；不足时才对**最少
  负载**节点发起优雅排空。排空中的节点立即拒绝新会话，在途会话先自然结束，
  超过排空超时再原子迁移（Rebind 要么整体提交要么留在原处），**不中断会话**。
- **失联 / 排空失败恢复**：节点失联后其承载会话成为孤儿并被重新调度，
  每个会话始终只绑定一个实例；无目的容量时保留孤儿以便后续重试，不丢失。
- **控制器重启恢复**：从持久化状态恢复 `desiredReplicas` 与操作日志，识别
  实际与期望差异继续收敛；通过幂等创建（按实例 ID 采纳）避免重复扩容，
  通过操作日志对账避免重复缩容，全过程写入事件日志可追溯。
- **超时/取消不留中间态**：创建失败即记终态（不计容量），后续 tick 自动
  重试；创建超时做补偿释放；排空超时不强杀，等待或迁移后才终止。
- **慢区域不阻塞快区域**：区域创建延迟相互独立，再平衡冷却按区域分别计时。
- **稳定状态不频繁迁移**：舰队处于在途创建/排空中、或偏离低于
  `rebalanceThreshold` 时不做再平衡，且迁移后有每区域冷却。

## 配置项

所有时间以"tick"为单位，`tickIntervalMs` 映射到墙钟时间。见
`internal/config/config.go` 的 `Default()`：

| 字段 | 含义 |
|------|------|
| `minReplicas` / `maxReplicas` | 弹性下限 / 上限（硬约束） |
| `scaleUpThreshold` / `scaleDownThreshold` | 平均利用率上/下阈值（构成迟滞死区） |
| `windowTicks` | 指标滑动窗口长度 |
| `scaleUpAfter` / `scaleDownAfter` | 需要连续越限的 tick 数 |
| `scaleUpCooldownTicks` / `scaleDownCooldownTicks` | 两次扩容/缩容之间的冷却 |
| `drainTimeoutTicks` | 排空超时；超过后把在途会话原子迁走再终止 |
| `opTimeoutTicks` | 创建等操作的超时与补偿 |
| `maxConcurrentOps` | 在途创建/排空操作的并发度上限 |
| `maxInstancesPerScale` | 单次决策最多调整的实例数（步长） |
| `rebalanceThreshold` | 触发再平衡的最小加权份额偏差 |
| `rebalanceCooldownTicks` | 每区域再平衡冷却 |
| `tickIntervalMs` | 一个 tick 的墙钟时长 |
| `regions[]` | `name/weight/spec/slowTicks/createFail/loseNodes` |
| `specs` | 规格名 → 单实例会话容量 |

## 运行

```bash
go run ./cmd/autoscaler     # 突增→回落演示，打印逐 tick 决策与事件
go test ./...               # 全部自动化测试
go test -race ./...         # 含竞态检测
```

## 测试覆盖

- 负载**突增**扩容且不超上限；负载**回落**经优雅排空收敛到下限。
- 阈值附近**波动不抖动**；相同输入**决策可复现**。
- **部分创建失败**后自动重试并在上下限内收敛，无悬挂 Pending 操作。
- 缩容中的**在途会话迁移**（粘性长会话不被中断、不跨区域）。
- **节点失联**后孤儿会话恰好一次重新放置，无丢失/重复占用。
- **控制器重启**后与不重启基线收敛一致，不重复创建/终止。
- **慢区域不阻塞快区域**；稳定舰队**不频繁再平衡**；再平衡不掏空区域。
